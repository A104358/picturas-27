Reúne os padrões arquiteturais mais comuns a considerar na identificação do padrão atual e na escolha das alternativas a comparar. Para cada padrão, indica-se o nível de análise e a relevância para o processamento de vídeo no PictuRAS.

Níveis de análise: padrão global e padrões locais

Um sistema combina, em regra, vários estilos arquiteturais em níveis diferentes. Antes de comparar alternativas, identifica o nível a que cada padrão atua:

  • Global: organiza a solução como um todo (decomposição em serviços, comunicação, entrada, implantação). É o padrão dominante e o contexto de todas as decisões locais.
  • Processamento de vídeo: organiza o caminho do vídeo dentro da solução. Pode seguir o padrão global ou afastar-se dele.
  • Interno a cada serviço: organização do código de um serviço (e.g., camadas).

Ao comparar alternativas, indica sempre se mantêm ou alteram o padrão global e avalia a coerência e o custo dessa opção. Um padrão local que se afasta do global pode ser uma escolha justificada ou uma fragilidade; em ambos os casos tem de ser fundamentado.

1. Padrões em Camadas (Layered)

  • Características:
    • Organização hierárquica
    • Separação clara de responsabilidades
    • Dependências unidirecionais
  • Variantes:
    • Strict Layered (comunicação apenas entre camadas adjacentes)
    • Relaxed Layered (permite bypass de camadas)
    • N-Tier Architecture
  • Nível de análise: interno a cada serviço.
  • Relevância: descreve a organização interna de cada serviço (e.g., rotas → controladores → modelos no projects), mais do que o processamento de vídeo.

2. Padrão Monolítico

  • Características:
    • Aplicação como única unidade
    • Simplicidade de desenvolvimento
    • Deploy único
  • Variantes:
    • Modular Monolith
    • Pipeline Monolith
    • Microkernel
  • Nível de análise: processamento de vídeo; como Modular Monolith, seria uma alternativa ao nível global.
  • Relevância: o video_tool concentra todos os efeitos de vídeo, a legendagem e a extração de fotogramas num único serviço (pipeline monolith dentro de uma arquitetura de microserviços).

3. Microserviços

  • Características:
    • Serviços independentes
    • Deploy independente
    • Bases de dados dedicadas
  • Variantes:
    • API Gateway
    • Sidecar Pattern
    • Service Mesh
  • Nível de análise: global (estilo dominante da solução); candidato também ao nível do vídeo.
  • Relevância: estilo global do PictuRAS e do caminho de imagens (um serviço por ferramenta); candidato para decompor o processamento de vídeo.

4. Event-Driven

  • Características:
    • Comunicação assíncrona
    • Desacoplamento
    • Escalabilidade
  • Variantes:
    • Publish-Subscribe
    • Event Sourcing
    • CQRS
  • Nível de análise: global (comunicação assíncrona entre serviços), com impacto no vídeo.
  • Relevância: RabbitMQ (video_queue, project_queue, ws_queue) e eventos video-progress; condiciona o modelo de progresso, de cancelamento e de recuperação.

5. Service-Oriented Architecture (SOA)

  • Características:
    • Serviços reutilizáveis
    • Contratos bem definidos
    • Enterprise Service Bus
  • Variantes:
    • Enterprise SOA
    • Domain-Driven SOA
    • RESTful SOA
  • Nível de análise: global (comunicação síncrona entre serviços).
  • Relevância: contratos REST entre apiGateway, projects e imageStorageService.

6. Pipes and Filters / Pipeline

  • Características:
    • Sequência de transformações independentes
    • Cada filtro tem entradas e saídas bem definidas
    • Reordenação e reutilização de filtros
  • Variantes:
    • Pipeline numa só unidade de processamento (decode uma vez, encode uma vez)
    • Pipeline distribuído (um serviço por filtro, como nas ferramentas de imagem)
  • Nível de análise: global (encadeamento de ferramentas) e processamento de vídeo (pipeline do vídeo).
  • Relevância: o encadeamento de ferramentas é a génese do PictuRAS; é o eixo principal da comparação imagem/vídeo.

7. Competing Consumers / Work Queue

  • Características:
    • Vários consumidores sobre a mesma fila
    • Escalabilidade horizontal e balanceamento de carga
    • Isolamento de cargas pesadas por fila dedicada
  • Variantes:
    • Réplicas estáticas
    • Autoscaling por tamanho da fila
    • Filas separadas por tipo de trabalho
  • Nível de análise: processamento de vídeo (alternativa que mantém o padrão global).
  • Relevância: o video_tool é um consumidor único (prefetch_count=1, sem réplicas), pelo que os vídeos são processados um de cada vez.

Considerações para Análise

  • Contexto do sistema
  • Padrão global da solução: coerência com ele e custo de se afastar dele ou de o alterar
  • Requisitos não funcionais críticos
  • Necessidades de evolução
  • Restrições tecnológicas
  • Custos operacionais
  • Risco de regressão funcional e custo do refactoring
  • Possibilidade de medir de forma reprodutível o efeito da alteração
